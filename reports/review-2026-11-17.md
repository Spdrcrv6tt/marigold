# External review, Nov 17, 2026: fixes needed

Reviewed at commit 3b37eb5 (tag model-v2-weights). Line numbers are for that commit.

How this was done:
- Two code reviews by reading: first the `model-v1...model-v2` range, then the whole tree.
- An independent rebuild on macOS (arm64, Python 3.14, NumPy 2.5): the golden models, the firmware's PC build and a C port of the wake spotter, all run against this repo's vectors.
- Nothing was simulated in Verilator and no training was run.

Each item is marked **read** (found by reading only, not executed) or **run** (reproduced by running code from this repo). Treat every **read** item as a claim to confirm before fixing.

## What reproduced, no action needed

- **Wake golden, format 2.** `sw/wake/golden/golden.py` (`run2`) on `rtl/wake/tb/vectors2` gives `expected.txt` line for line on all three cases (36,588 trace lines). An independent C port of `fe.py`, `golden.py` and `rtl/model/vad_model.py` gives the same lines, and its VAD flags equal `vad.json`.
- **Intent model v2.** `sw/golden/intent_np.py` and `chip_golden.py` with `weights/mg-v2.npz` reproduce all four release vectors: every trace, the tokens, the raw values, the match, the host frame and the stream events.
- **Firmware PC build.** `marigold.c` + `hal_host.c` with the image from `mkimage_mg.py data --tag v2` give the same q and raw values as the vectors on the four stored segments and the four stream segments, with 253,952 bytes of RAM.

## rtl/ (core agent)

**R1. Sample index wraps after 74.6 hours of listening** (read). `rtl/top/mg_capture.sv:93`
- Problem: `wp` is 32 bits and counts every sample. The segment-start logic uses absolute compares (`wp > pre`, `kp > last_end`, `wp - 256 >= kw`) that are not wrap-safe.
- Effect: at the first wake after the wrap, `last_end` still holds the pre-wrap value, so the segment starts there. The reader then delivers hours of stale indexes at full core rate and `c_cap` never fires. A segment open across the wrap closes as a false TIMEOUT. The Python model uses unbounded ints, so no test can see it.
- Fix: make the compares modular (differences only), or rebase `wp`, `last_end`, `kw`, `sstart` and `rp` together whenever no segment is open or queued.
- Check: a capture test that presets `wp` near 2^32 and runs wakes across the wrap against `mg_model.Segmenter`.

**R2. Core and island can livelock when a second segment is queued** (read). `rtl/core/fw/hal_rv.c:123`, `rtl/top/mg_capture.sv:68`
- Problem: `mg_power_off()` is `for (;;) SLEEP(8)` and `marigold.c` handles one segment per power-up. The island answers a sleep request with "wake at once" whenever another segment is queued.
- Effect: a second wake that opens a segment after segment 1's end marker but before the firmware sleeps is never read. The core wakes and sleeps forever, `osc_en` stays high, and the host gets WAKE frames but no COMMAND or NOMATCH until reset.
- Fix: either power-cycle the core when a segment is waiting (so it boots and reads it), or have the firmware loop back to read the next segment instead of sleeping forever.
- Check: a whole-chip run with a second wake placed in the 21 to 35 ms after a segment closes. `fw_smoke.c` and the `test_cap.py` core model both keep reading after `dq`, so they do not cover it.

**R3. The committed LUT ROM is model v1's** (run). `rtl/core/imh_rom.svh`
- Problem: `mkimage_mg.py rom` for v1 reproduces the committed file exactly; for v2 it differs in 513 lines, one 513-entry table (the asinh table depends on each export's `fe.k`). `regress_mg.sh` overwrites the tracked file in the working tree, and the v2 commit did not include it.
- Effect: a fresh clone at `model-v2` builds RTL that is not bit-exact with the v2 golden model.
- Fix: commit the v2 `imh_rom.svh` with the model tag, and make `mkimage_mg.py data` an error (not a warning) when the ROM does not match the export.
- Check: `mkimage_mg.py rom --tag v2 --golden-dir weights --out <dir>` then compare with the tracked file.

**R4. The blob's D is never checked against the model's** (read). `rtl/core/fw/marigold.c:316`
- Problem: the firmware reads D from the blob but writes only `MG_D` bytes of q. The loader accepts any D from 1 to 256.
- Effect: a D = 256 blob on the D = 128 model loads as valid and `mg_match` sums q[128..255] from words never written. `chip_golden.run_stream` raises for the same input; the chip gives no error.
- Fix: reject at load (a config error code) or in the firmware (NOMATCH plus a flag) when the blob's D differs from the model's. See K7 for the SDK side.
- Check: load a D = 256 blob in `test_cfg.py` or the whole-chip harness and require the error.

**R5. Listen-off during an open segment leaves the core powered** (read). `rtl/top/mg_ctl.sv:182`
- Problem: dropping `listening` stops the sample stream but does not close an open segment; `mg_capture` has no abort input.
- Effect: `on`, `rd_act` and `osc_en` stay set for the whole mute, and on un-mute the stale segment resumes with audio spliced across the gap.
- Fix: close the segment (as TIMEOUT or a new abort marker) when listening drops.
- Check: `test_ctl.py` with CTRL listen-off inside the listen window.

**R6. A config reload during a match corrupts the matcher's inputs** (read). `rtl/top/mg_cfg_load.sv:96`
- Problem: CTRL begin zeroes the header registers that `mg_match` and `mg_gpio` read live, with no interlock for a match in progress.
- Effect: D reads 0, the matcher runs until `ii` wraps (seconds) over half-written SRAM, drops the next `m_go`, and raises an event with GPIO rules from garbage scores.
- Fix: abort the match on CTRL begin, or hold the load until the matcher is idle.
- Check: `test_cfg.py` with CTRL begin injected while `m_busy`.

**R7. I2C SDA timing is marginal at 400 kHz** (read). `rtl/top/mg_i2c.sv:86`
- Problem: SDA changes two to three `clk_fe` periods (651 to 977 ns) after the SCL fall. The fast-mode maximum for tVD;DAT and tVD;ACK is 0.9 µs.
- Effect: with tLOW at its 1.3 µs minimum and a 300 ns rise, a released SDA settles with under 100 ns of setup. `test_ctl.py` passes because its bus model has zero rise time.
- Fix: drive SDA from the first synchronised SCL-low sample, or document 100 kHz only.
- Check: add rise time to the bus model and run at the fast-mode minimum.

**R8. Ack resync race after core power-off** (read). `rtl/top/mg_capture.sv:145`
- Problem: resetting `ack_seen` while `ack_s[1]` is still 1 produces a spurious `ack`.
- Effect: in a one-to-two clock window either delivery starts at the previous segment's end, or `outst` clears and both sides wait forever.
- Fix: clear `ack_seen` only after the ack synchroniser has settled low, or resynchronise both together.
- Check: a directed test with a wake on the `dq` edge and the one after, core having acked an odd number of times.

**R9. `regress_mg.sh` cannot fail** (read). `rtl/top/regress_mg.sh:30`
- Problem: every check runs in the background, a bare `wait` drops their exit codes, and the script's status is the last `tail | cut`.
- Effect: a positive that is not bit-exact, or a negative control that wrongly passes, still gives exit 0. `mg_e2e.py` itself returns a proper status.
- Fix: record each PID, `wait` on each, and exit non-zero if any failed.
- Check: stub one child to exit 1 and require a non-zero status.

**R10. A failed step falls back to stale artifacts** (read). `rtl/top/regress_mg.sh:11`
- Problem: the ROM install is an unchecked `&&` chain and both chip builds are backgrounded with status dropped. `chip.mk` leaves the old `obj/sim` in place on failure.
- Effect: the e2e runs can test the previous build and report bit-exact. This is the same failure the range already hit in `test-mac`.
- Fix: check each step and delete `obj/sim` before building.

**R11. Hard-coded home directory** (read). `rtl/top/regress_mg.sh:21`
- Problem: the patched blob is written to `/home/johnmc/.marigold/build/` but read from `$MARIGOLD_BUILD`.
- Fix: write to `$MARIGOLD_BUILD`.

**R12. The whole-chip harness always runs with the trace strap on** (read). `rtl/top/tb/mg_main.cpp:155`
- Problem: `+trace=1` is the default and `mg_e2e.py` and `mg_smoke.py` never override it. With trace on, the firmware waits for the matcher before powering off.
- Effect: the product path (power-off right after MATCH_GO, core reset while the matcher runs) and its timing have never been simulated.
- Fix: run the regression with `+trace=0` as well. The checks use only bridge-write and frame logs.

**R13. Default test entry points miss the shipped configuration** (read). `rtl/Makefile:6`
- Problem: `BLOCKS` omits cfg, ctl and cap; `rtl/wake/tb/run.sh` defaults to format 1; `test-mac`'s default fixtures no longer match the committed LUT ROM.
- Fix: make the defaults run what `marigold_top` instantiates, and have `regress_mg.sh` run the island tests.

**R14. Dead accept handshake in the matcher** (read). `rtl/top/mg_match.sv:144`
- Problem: no transition enters `S_WAIT`, so `waiting`, `m_emit`, MATCH_GO read bit 3 and the testbench emit branches never fire; `fa` is write-only.
- Fix: delete them. Behaviour is unchanged.

**R15. Unbuildable Poinsetta leftovers** (read). `rtl/top/Makefile:50`
- Problem: `host`, `image`, `sim-rom`, `sim-flash`, `sim-cov`, `host-ts` and `image-ts` reference files not in the repo, and `imh_core.sv`, `imhotep_top.sv`, `imh_capture.sv`, `stream.c`, `model.c` and `imh_rom_poinsetta.svh` duplicate the Marigold files.
- Fix: drop them or move them to a reference directory; `PROVENANCE.md` already records the source commit.

**R16. A missing value cannot be told from the slot's minimum** (run). `rtl/model/mg_model.py` `island_value`, architecture 8.2
- Problem: when the value head finds no value, the raw slot value is 0, and the island clamps it to the slot's minimum.
- Effect: "power level five" from a voice the value head missed arrived as COMMAND power_level with power = 1 (observed). By the same rule a "start" with no parsed time arrives as start, 1 s. The host cannot tell "not said" from "said the minimum".
- Fix: carry a value-present bit per slot in the frame, or a reserved raw code that the island passes through unclamped. This changes the frame format, so it needs a ruling.

## sw/ (model agent)

**S1. The learned reject threshold is never restored** (read). `sw/intent/train.py:354`
- Problem: the final checkpoint omits `thr` (only the every-1000-step saves include it) and line 256 always re-initialises `thr_p` from `--thr0`. Line 299 clamps it to [0, 0.9], so outside that range its gradient is zero.
- Effect: QAT starts from `f6-final.pt` with the threshold back at 0.45, and every crash-resume resets it again.
- Fix: save `thr` in the final checkpoint, load it from `--init` when present, and clamp the parameter after the optimiser step instead of in the forward pass.
- Check: a save and load round trip in a short run.

**S2. `--moonshine --lr-pre` stops applying after a resume** (read). `sw/intent/train.py:235`
- Problem: `pre` is filled only when `--init` is empty.
- Effect: after the first crash, `--init at6-resume.pt` leaves `pre` empty, so the pretrained weights jump from 0.3x to the full learning rate and the schedule restarts.
- Fix: derive the pretrained tensor names whether or not `--init` is set, and carry the step into the scheduler.

**S3. Curly apostrophes defeat the eval-leak check** (read). `sw/data/tts_build.py:339`
- Problem: `cmd_jobs2` uses `EvalFilter`, whose `norm` turns U+2019 into a space, while the same line lets U+2019 through the ASCII check.
- Effect: "i don’t know" normalises to "don t" and does not match the eval line "i don't know". Whether such lines exist in the data was not checked.
- Fix: fold the apostrophe in `EvalFilter.norm`, as `tts_build.norm` (line 45) does.

**S4. The leak filter does not cover the new eval sets** (read). `sw/textfilter.py:503`
- Problem: the shared filter covers `eval/text_v2` only, not `eval/text_v3` or `eval/text_dev2`. `make_reject_bank.py:25-29` patches a private copy.
- Fix: extend the shared filter and delete the private copy.

**S5. Pipeline "done" markers are written on failure** (read). `sw/intent/run_final_v2.sh:25`
- Problem: the freeze pipelines write `=== done` unconditionally to append-only logs, and `run_resume.sh` exits 0 when every attempt crashed. In `run_c.sh` the qv3 QAT call has no guard.
- Effect: `run_regress.sh` starts the regression on whatever `mg-<tag>.npz` is on disk, and a marker from an earlier attempt satisfies a re-run's wait at once.
- Fix: write the marker only on success, with a per-run id; exit non-zero when attempts run out.

**S6. The enrollment speech bank moves with the training index** (read). `sw/intent/evaluate.py:169`
- Problem: the bank is `[::7][:1500]` of the mutable index.
- Effect: the report says microwave v1 moved by up to 3 points for this reason, which is more than several v1-versus-v2 deltas in the section 9 table.
- Fix: select the bank by a stable key or a frozen list file.

**S7. "Rejection off" still counts reject-prototype wins as rejects** (read). `sw/intent/evaluate.py:236`
- Problem: it disables only the threshold and the margin.
- Effect: the "(rejection off)" figures understate pure action confusion, more so as bank prototypes are added.
- Fix: add a mode that masks action-0 prototypes and report both.

**S8. The wake network misses on a digitally silent background** (run). `sw/wake/`
- Measured: "Hey kitchen" from two of three macOS voices did not fire when the surrounding audio was exact zeros, and fired once a noise floor of about 60 LSB RMS was added at the same speech level (0.3 of full scale peak). The VAD was on in both cases; the peak keyword score at wake_sens 13 moved from -53 and -40 to +34 and +42. With gating off the silent versions still did not fire, so it is the network.
- Effect: clean TTS fed straight in, or any digital audio path, can miss wakes.
- Fix: include zero and near-zero noise floors in the wake training augmentation.

**S9. Line endings** (read). `sw/intent/run_resume.sh`, `sdk/compile.py`, `sw/intent/evaluate.py`, `sw/textfilter.py`, `docs/licenses.md`
- Problem: five files flipped from LF to CRLF in the v2 range, so a 35-line change to `evaluate.py` shows as 267 added and 274 removed, and `run_resume.sh` has a CRLF shebang.
- Fix: restore LF and add a `.gitattributes`.

## sdk/ (SDK agent)

**K1. The default embedder changes silently and the blob records neither teacher nor model** (read). `sdk/compile.py:318`
- Problem: the default becomes teacher-v4 once that directory exists, while `sw/intent/evaluate.py:131` still defaults to teacher-v3.
- Effect: a config compiled for a model-v1 chip without `--embedder` loads fine and matches garbage, and nothing detects it.
- Fix: one shared default, printed on every compile; record the teacher and model tag (in the blob if the format allows, else in a sidecar the loader tools check).

**K2. The shipped microwave config rejects almost every command from a new voice** (run). Blob carried by the release vectors (N 176, reject_thr 86,291).
- Measured: 6 macOS voices not used for enrollment or tuning, 14 lines each (5 typed examples, 5 unseen phrasings, 2 non-commands, 2 with no wake phrase), through this repo's own golden chain (VAD, wake format 2, segmenter, IntIntent, matcher). Typed commands, right action: 7 of 30. Unseen phrasings: 0 of 30. Non-commands rejected: 11 of 11. Wake phrase heard: 71 of 72. With the reject rule off, the closest action prototype was right for 22 of 30 typed and 19 of 30 unseen. The median best action score was 41,624 against the threshold of 86,291, and a reject prototype won 45% of the time.
- Same voices with a blob built by `enroll_protos` (audio + bank + calibration, 32 prototypes per action) from ten other macOS voices, threshold picked on four more by the `pick_thr_margin` rule: typed 22 of 30, unseen 8 of 30, non-commands rejected 10 of 11.
- Limits: synthetic macOS voices, small sample, one product.
- Fix: do not ship text prototypes with a text-calibrated threshold for audio. Make audio enrollment plus an audio-calibrated threshold the SDK default, and report rejection-off accuracy beside the end-to-end number so the two failure modes stay separate.

**K3. The 32 KB budget is not enforced on the default enrollment path** (read). `sdk/compile.py:368`
- Problem: `enroll_protos` checks the budget only when `text_reject` is set.
- Effect: 7 actions at K_audio 32 plus 16 reject and 32 bank prototypes is 272 x 132 bytes = 35.9 KB, over `MAX_BLOB`. `evaluate.py` packs it without parsing, so an evaluation can choose a variant the chip cannot load.
- Fix: enforce the budget on every path and parse what was packed.

**K4. A reject bank is ignored unless `--bank-protos` is also given** (read). `sdk/compile.py:424`
- Problem: the default is 0, and the bank's saved `teacher` field is never checked against the embedder.
- Fix: error when a bank is given with zero prototypes, and check the teacher.

**K5. `expand.py` and `compile.py` disagree on the expansion file** (read). `sdk/expand.py:47`
- Problem: `expand.py` writes `data/expand/expanded.json`; `compile.py` and the tests read `expanded_qwen25.json` and continue without it. `expand.py` is hard-wired to fan and microwave and does not dedupe a paraphrase the LLM emits under two actions.
- Effect: the blob is built from typed examples only, with no reject prototypes and the placeholder threshold, and no error.
- Fix: one filename, an error when it is missing, any product, and a cross-action dedupe.

**K6. Five SDK tests never run in script mode** (read). `sdk/tests/test_compile.py:135`
- Problem: the `__main__` runner sits mid-file, so the tests defined after it do not run with `python sdk/tests/test_compile.py`, and `test_real_embedder` returns silently when skipped.
- Fix: move the runner to the end.

**K7. `--dim` defaults to 256 while the model's D is 128** (read). `sdk/compile.py`, tests assert D == 256
- Fix: take D from the model export or the teacher projection; pair with R4.

## docs and reports

**D1. "Within about a point" is contradicted by the result files beside it** (read against the JSON). `reports/p0-model.md:228`
- Problem: `eval-f6.json` against `eval-golden-v2.json` for the microwave: clean unseen 43.9% to 39.7%, microwave noise 10 dB 35.7% to 27.9%, `eval/text_v2` 30.0% to 25.3%. Only the fan is within a point.

**D2. Boot time in the architecture doc is ten times too low** (read). `docs/architecture.md:59`
- Problem: it says about 16 KB at 16 bytes per clock, under 15 µs. `mg_core.sv:322` copies one byte per clock: about 14,400 clocks, roughly 147 µs at 98.3 MHz.
- Fix: correct it and label it as derived, not measured.
